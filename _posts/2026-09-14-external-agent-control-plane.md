上一篇（[ACP 协议两个关键语义与看门狗架构](/2026/09/13/kiro-acp-worker-supervisor/)）讲的是"接入"。这一篇讲**全景**：把 LLM 会话当操作系统进程来管的一整套控制面——四层架构、五个核心机制、一夜跑通验收驱动开发的完整记录、以及十个用真实代价换来的踩坑。所有机制都在生产环境验证过。

## 一、要解决的问题

让多个 LLM Agent 会话（Kiro CLI）在同一台服务器上**并行干活**：写测试、修基础设施、合并分支、建知识图谱、跑发布冒烟——并且：

- 挂了要有人管（心跳、重启、续跑不丢上下文）
- 完成要有人验（不采信 agent 的自我报告）
- 资源要不打架（端口/浏览器登录态/worktree/发布产物）
- 报告要可回放（每一步的输入、操作、返回、断言全部留痕）

## 二、总体架构：一个微型操作系统

```
┌─ 策略层 ──────────────────────────────────────────────┐
│ 任务书(mission) · steering(R1-R8) · hook(60s 硬拦)      │
├─ 监督层 ──────────────────────────────────────────────┤
│ supervisor(监督器)：spawn/wait/看门狗/验收器/续跑回喂    │
│   └─ worker：ACP 客户端 + 心跳 + 权限自动批准           │
├─ 资源层 ──────────────────────────────────────────────┤
│ resreg(CMDB) · Chrome 一线一实例 · 加密凭据(.env)       │
└─ 状态层 ──────────────────────────────────────────────┘
  BASE 前缀文件：mission/resume/done/sessionid/heartbeat/result/verify
```

**机制与策略分离**：监督层只提供机制（心跳、重启、验收），策略全在任务书里（超时上限、完成判据、资源纪律）——改策略不用改机制。

## 三、五个核心机制

### 1. ACP 接入：LLM 会话即子进程

`kiro acp` 在 stdio 上暴露 ndjson JSON-RPC：`initialize → session/new → session/prompt → 流式 session/update → stopReason`。控制面就是一个 Python 脚本。三个实测语义：

- **一个会话同时只接受一个 prompt**（"Prompt already in progress"）——所以探活只能靠外部心跳，不能靠插话
- **后台工具调用可行**：nohup 启动秒回 end_turn，进程真实存在，期间前台对话正常——长任务标准姿势 = nohup + 哨兵文件 + 逐轮查哨兵
- **session/load 续跑**：worker 重启后 load 同一会话，上下文不丢

### 2. Supervisor：监督器 = 生命周期总管

每条任务线一个 supervisor（300 行 Python）：

```
循环：
  spawn worker（读任务书）→ 20s 轮询心跳文件
  ├─ 心跳静默 15 分钟 → 判定挂死 → 杀进程树 → 冷却 → 重启（会话经 session/load 续跑）
  └─ worker 退出：
       ├─ 验收器绿 → 完成标记 → 退出
       ├─ end_turn 无完成标记 → 下一轮续跑（阶段间停顿，不占重启额度）
       └─ 异常/超时/挂死 → 冷却 → 重启（上限 30 次，防 credit 失控）
```

**Watchdog（看门狗）与 Supervisor 的分工**：心跳活性检测是 watchdog 模块（20s 轮询、15min 静默判死）；生命周期编排是 supervisor 职责。命名上 `kiro_tdd_supervisor.py` 符合行业惯例（同物：supervisord、systemd、PM2）。

### 3. 验收器：完成判据 = 可执行的测试

这是整套体系最重要的一刀：**不采信 agent 自我报告**。

```
worker end_turn（自称完成）
   ↓
supervisor 亲自跑 verify.sh（真实测试套件）
   ├─ exit 0 → 写完成标记，任务结束
   └─ exit 1 → 把测试器失败输出原样回喂 agent：
        "你自称完成，但客观验收未通过，以下是失败清单……继续修"
```

TDD 的完成判据本身就是可执行的——所以"完成"根本不需要匹配魔法字符串，**跑测试看退出码**，agent 想掺水都掺不进去。实战价值：今晨某会话声称"build #109 SUCCESS"，当晚客观验证发现该 job 在 622 个 job 里根本不存在，而 URL 200 其实来自更早的残留部署——叙述与事实的差距被精确抓住。

### 4. 资源三件套：并发不打架

| 资源 | 竞争形态 | 隔离手段 |
|---|---|---|
| 浏览器登录态 | 一处登出全组遭殃 | 一线一 Chrome 实例（独立 CDP 端口 + 独立 user-data-dir）+ resreg 登记 |
| 同仓库文件系统 | 切分支互相踩 | git worktree（每线一个） |
| 发布产物 | 同名覆盖 | 时间戳命名 + 只增不删 |
| 共享 CI job | 并发触发 | 天然串行化（Jenkins 排队） |
| 注册表 | 并发写覆盖 | flock + 原子换名 |

配套一个 **resreg 轻量 CMDB**（claim/check/list/release/gc）：独占资源使用前必须登记，**即使空闲但已被 claim 也不得使用**——owner 随时可能起进程。规则写入 steering，所有会话动态可见。

### 5. 报告证据链：四要素逐步可回放

验收报告不是"跑通了"，而是每一步四要素：

- **输入**：打开的 URL / 进入的会话 / 发送的原话（逐字）
- **操作**：找到的控件（selector）、执行的命令、触发的构建号
- **返回**：页面呈现 / agent 回复原文 / HTTP 状态 / 构建结果
- **断言**：对返回做了什么断言及结果；证据 = 截图/日志/产物路径

人读 `.md` + 机器读 `.json` 双份。审计迭代：跑一遍 → 逐阶段对照规范查缺 → 缺什么当场补 → 重跑 → 直到逐步可回放。

## 四、一夜实录：验收驱动开发全链路

时间线（2026-09-13 晚 → 09-14 凌晨）：

```
PRD 审查（只读会话）→ 发现发布域 PRD 与实现漂移【高危】→ 修复回填
测试先行：全旅程 e2e 套件上库（b4b7dba，2绿/5skip/0红）
基础设施：JWT 铸造打通（发现双令牌体系）→ Jenkins job 缺失 → Groovy 创建
构建迭代：#1 分支错 → #3 沙箱 → #5/#6/#7 三个流水线 bug → #8 SUCCESS
URL：https://smoke-20260914042045-14409.jereh-pe.cn 三重验证 200
复现：全新会话从零重跑 → 3.3 分钟 → build #9 SUCCESS → URL 200 ✅
旁路：知识图谱入 Neo4j（622 个 Jenkins job + 资源拓扑）· PR #17 合并
```

每一个" FAILURE→SUCCESS"都对应一个真问题被修掉；每一步都有客观证据（构建日志/HTTP 状态/退出码），没有一步依赖口头汇报。

## 五、踩坑清单（每条都有真实代价）

1. **pkill 自匹配**（踩三次）：模式串出现在同一命令行任何位置都会自杀——最终形态：清理一律 environ 定向扫描 + kill PID，或 PID 文件管理
2. **"设了但为空"≠"没设"**：`os.environ.get` 拿到空串覆盖默认值 → worker 空转半小时（LOAD_FAIL 循环）
3. **done 文件双义**：agent 把"阻塞报告"写进 done 文件 → 上层误判完成。教训：完成判据必须是验收器（可执行），done 只是快捷捷径；阻塞要有独立通道
4. **验收器时序 bug**：验收器代码插在 `reason` 计算之前 → 拿到陈旧状态 → **从未真正执行过**——"加了验收"和"验收真的在跑"是两回事，要自测验收器本身
5. **Groovy API 版本漂移**：`createRepoList(String, credId)`、`setSandbox` 不存在、`approveSignature` 要签名字符串——隔空手搓必错，这类活交给 Kiro 会话自己内省迭代
6. **双令牌体系**：IAM 网页登录产出 cookie 会话，发布流水线要的是本地自签 JWT（HS256 + 平台密钥）——两码事，浏览器登录是弯路
7. **沙箱损坏条目**：approvedSignatures 里混入裸哈希和对象 toString，导致一切审批失败且报错只有 8 位哈希——清理比批准优先
8. **nohup 丢 PATH**：nvm 只在交互 shell 加载，后台脚本要显式补 PATH
9. **rm glob 自删**：`rm -f /tmp/xxx-*` 把刚写的任务书一起删了——清理用精确文件名，或放在写文件之前
10. **越俎代庖**：API 试错类工作（Groovy 签名漂移）自己手搓三次不如 Kiro 会话自己内省一次——**主管的职责是派活和验收，不是替 agent 打仗**

## 六、角色命名（对齐行业术语）

| 我们的角色 | 行业术语 | 职责边界 |
|---|---|---|
| kiro_tdd_supervisor | **Supervisor**（监督器） | 生命周期：启动/监视/重启/验收/续跑 |
| 心跳巡检模块 | **Watchdog**（看门狗） | 只管活性：心跳超时判死 |
| verify.sh | **Verifier**（验收器） | 只管完成判据：可执行断言 |
| （未来）多服务器统一调度 | Orchestrator | 排兵布阵，还没到 |

## 七、已知债务与下一步

- **问答回路缺失**：agent 中途提问（如"矩阵改哪个分支"）无应答通道 → 40 轮空转或误写完成标记。方案：`$BASE-question/$BASE-answer` 信箱
- **操作入口缺失**：状态/杀线/回话全靠手搓 SSH（事故高发层）。方案：`opsctl` 统一 CLI
- **状态在 /tmp**：重启丢 sessionid。方案：迁 `~/.local/state/kiro-ops/`（已落地）
- **契约测试缺位**：跨仓库接口高频变更，全链路 E2E 频率不够
- **单点**：supervisor 自发死亡无人管（实测两起均为人工误杀；夜间值守 monitor 评估后未常驻）

## 结语

把 LLM 会话当进程管，核心不是什么复杂框架，而是把操作系统的老智慧搬到新物种上：**心跳、监督、资源登记、客观验收、证据留痕**。Agent 会说谎、会遗忘、会卡死——所以完成判据必须可执行，恢复必须自动化，报告必须可回放。

一夜之间，这套控制面跑完了 PRD 审查→漂移修复→测试先行→基础设施补齐→真实构建→URL 三重验证→全新会话复现的完整闭环。**全绿不是喊出来的，是验收器跑出来的。**
