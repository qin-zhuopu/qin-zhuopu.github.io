在动任何破坏性操作（禁用插件、restore、批量改数据）之前，先打一个备份是肌肉记忆。`nb` CLI 把 NocoBase 的备份/恢复能力包成了 `nb backup` 和 `nb api backup` 两组命令，其中 `nb backup create` 最省心：服务端创建备份包并自动下载到当前目录。

## 命令用途

NocoBase 的备份是一个 `.nbdata` 包，包含应用配置与业务数据，既用于回滚也用于跨实例导入。CLI 提供两层入口：`nb backup` 是面向人的快捷入口，`nb api backup` 是更细粒度的服务端 API 封装。常用命令：

- `nb backup create`：在服务端创建备份，并自动下载 `.nbdata` 文件到本地当前目录。
- `nb api backup list`：列出服务端已有的备份文件。
- `nb api backup status` / `restore-status`：查询备份与恢复任务的执行状态。
- `nb api backup download`：手动下载指定备份。
- `nb api backup restore` / `restore-upload`：从服务端备份 / 上传的备份文件恢复（**破坏性**）。
- `nb api backup remove`：删除服务端备份。

## 语法与常用参数

```bash
# 一条命令完成"服务端打包 + 自动下载"
nb backup create

# 查看服务端已有备份
nb api backup list

# 恢复前先盯状态（异步任务）
nb api backup status
nb api backup restore-status
```

需要精细控制时用 `nb api backup`：`restore` 从服务端已有备份恢复，`restore-upload` 把一个本地的 `.nbdata` 上传后恢复（适合把 A 实例的备份灌进 B 实例），`download` 手动下载，`remove` 清理服务端存储。`nb backup create` 相当于把"服务端创建 + 下载"两步合并成一条命令，日常够用。

## 实测效果

```bash
$ nb backup create
# 服务端创建备份并下载到当前目录
# backup_20260908_215255_9761.nbdata
# 全程约 24~40 秒（视数据量与网络）

$ nb api backup list
# 列出服务端备份文件，含文件名与创建时间
```

文件名规则是 `backup_<时间戳>_<序号>.nbdata`，下载完成后本地和服务端各留一份，双保险。

一组典型的"改动前保险动作"：

```bash
nb revision create "改动前：完成 CRM 页面一期"   # 配置层安全点
nb backup create                                 # 数据层快照
# ... 开始做破坏性改动 ...
# 出问题时：nb api backup restore 从刚才的备份恢复
```

## 踩坑点

- **文件名里的时间戳是 UTC**。实测在本地时间 9 月 9 日凌晨 05:52 执行，落盘文件名却是 `backup_20260908_215255`——差了 8 个时区。按文件名找"今天最新的备份"时千万别按本地日期过滤，要么以 `nb api backup list` 返回的时间为准，要么统一转成 UTC 再比。
- `restore` 是覆盖式恢复，会把实例回滚到备份时刻，**未实测也不敢在共享实例上试**；执行前务必确认目标实例没有别人的在途数据。
- 备份/恢复都是异步任务，发起后要看 `status` / `restore-status` 确认完成，而不是等命令返回。
- 下载发生在当前工作目录，先 `cd` 到打算放备份的目录再执行 `nb backup create`，免得散落在 `~` 下。
- 备份包包含业务数据，属于敏感文件：不要提交进 git，也不要随手放在 Web 可访问目录里；建议集中放一个专用目录并纳入备份归档策略。

## 什么时候用

- 任何结构性改动前（插件启停、集合删除、工作流大改）：先 `nb backup create` 留一个可回退的快照。
- 迁移/归档场景：`create` 拿到 `.nbdata` 后可带到别的实例用 `restore-upload` 导入（跨环境迁移则是 `nb api migration` 那一套数据迁移包）。
- 定期巡检：`nb api backup list` 看服务端是否已有近期的备份，避免重复打包。
- 与其他保护手段的分工：`nb revision` 保应用配置快照（轻、快），`nb backup` 保配置 + 数据（重、全），`nb api migration` 负责跨环境的数据迁移包。日常小改动用 revision，大动作前两者都做。

## 命令速查

```bash
nb backup create                 # 服务端打包 + 自动下载
nb api backup list               # 服务端备份清单
nb api backup status             # 备份任务状态
nb api backup download           # 手动下载
nb api backup restore            # 从服务端备份恢复（破坏性）
nb api backup restore-upload     # 上传 .nbdata 恢复（破坏性）
nb api backup restore-status     # 恢复任务状态
nb api backup remove             # 删除服务端备份
```

记住三件事即可：改前先 `create`、文件名时间戳是 UTC、`restore` 前想清楚它会把实例整体回退。
