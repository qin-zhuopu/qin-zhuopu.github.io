`nb api app` 是一组应用级命令：看实例基本信息、看运行时插件、清缓存、重启。平时用得不多，但排障时几乎每个问题都会路过它。这篇把五个动作按「敢不敢随手执行」分个类。

## 命令用途

| 命令 | 作用 | 风险 |
|------|------|------|
| `get-info` | 实例基本信息（数据库方言、版本、语言、名称、主题） | 无，只读 |
| `get-plugins` | 运行时插件元数据 | 无，只读 |
| `get-lang` | 语言与全部 i18n 资源 | 无，但输出巨大 |
| `clear-cache` | 清服务端缓存 | 低，会短暂变慢 |
| `restart` | 异步重启应用 | 高，会中断服务 |

## 语法与常用参数

```bash
nb api app get-info
nb api app get-plugins
nb api app get-lang
nb api app clear-cache
nb api app restart
```

都不需要额外参数（部分版本支持 `--locale` 之类，以 `--help` 为准）。

## 实测效果

`get-info` 的返回（节选）：

```json
{
  "name": "demo",
  "version": "2.4.0-alpha.4",
  "lang": "en-US",
  "theme": "default",
  "database": { "dialect": "postgres" }
}
```

一条命令就知道：实例跑的什么版本、连的什么库、界面语言是什么。排查兼容性问题（比如插件要求某个最低版本）时这是第一站。

`clear-cache` 执行成功后没有花哨的输出，就是静默完成。清完之后首次访问页面会明显变慢（缓存重建），属正常现象。

## 踩坑点

**1. `get-lang` 的输出非常大。** 它返回的不只是一个 `lang` 字段，而是**所有插件的 i18n 资源全集**——每个启用的插件的中英文案都在里面，轻松几十万字符。在终端里直接跑会把屏幕刷满，脚本里也务必重定向到文件或先 `jq` 过滤，只取需要的部分：

```bash
nb api app get-lang > /tmp/lang.json
jq '.lang' /tmp/lang.json
```

**2. `restart` 是异步的。** 命令返回不代表重启完成，共享实例上更要谨慎——它是真重启，所有在线用户会被打断。实测时我选择不执行，只确认了命令存在。

**3. clear-cache 不是万能药。** 「界面改了不生效」先刷新浏览器、检查前端缓存，clear-cache 解决的是服务端缓存那部分。乱清缓存对多用户实例反而是干扰。

**4. 版本号可能是 alpha。** 实测返回 `2.4.0-alpha.4`，说明实例跑的是预发布版本，遇到子命令缺失（比如上一篇 ACL 里的 desktop-routes）先看版本，很可能是版本差异而不是用法错误。

## 什么时候用

- `get-info`：接手任何实例的第一条命令，确认版本与数据库
- `get-plugins`：核对某插件是否真的在运行时加载（和 `nb api pm list` 的静态元数据互补）
- `get-lang`：改文案、查翻译 key 时用，记得落盘过滤
- `clear-cache`：升级插件或改了服务端配置后不生效时
- `restart`：留给维护窗口，且提前通知用户

一个组合技：`get-info` 确认版本 → `get-plugins` 确认插件加载 → `clear-cache` 排除缓存干扰，三步走完，「这功能到底支不支持」这类问题基本都能定性。
